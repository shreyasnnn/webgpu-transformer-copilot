# Phase 04 — Mechanical Hardware (Clamps & Bobbins)
## File: 06-svg.md

> **Scope:** This is the PRIMARY documentation for all SVG diagrams in the project.
> Both SVG instances (inline card diagram and modal diagram) are first populated
> and updated in Phase 4 Step 13 and at the end of `calculate()`.

---

## Overview

The project contains ONE SVG bobbin blueprint diagram, which appears in TWO locations:
1. **Inline SVG** — embedded in the Step 13 calculation card within the main page.
2. **Modal SVG** — a duplicate embedded inside the summary modal (`#summaryModal`).

Both SVGs are **STATIC geometry** defined in `index.html`. Phase 4 Step 13 updates
only the **text label values** inside the SVG — the geometry (rectangles, lines) is
not dynamically generated or modified.

---

## SVG Instance 1 — Inline Bobbin Blueprint (Step 13 Card)

### SVG Identification
- **Container:** Inside the Step 13 `.step-card` section in `index.html`
- **SVG element:** `<svg>` with class `bobbin-svg` (or similar — static geometry)
- **Purpose:** Live visual diagram of bobbin cross-section dimensions that updates
  as the user changes inputs.

### Static SVG Geometry (defined in HTML — never modified by JS)
The SVG contains two concentric rectangles representing the inner cavity
(core fit) and the outer bobbin shell, with dimension lines and leader labels.
The geometry is drawn using absolute coordinates in the SVG viewport.
No geometry is recomputed by JavaScript.

### Dynamic Label Elements

| Element ID   | Label Displayed       | Value Source            | Null Fallback |
|--------------|----------------------|-------------------------|---------------|
| `#svg_a`     | `a = {value}`        | `bobbinInnerW` (mm)     | `"a = --"`    |
| `#svg_b`     | `b = {value}`        | `bobbinOuterW` (mm)     | `"b = --"`    |
| `#svg_c`     | `c = {value}`        | `bobbinInnerL` (mm)     | `"c = --"`    |
| `#svg_d`     | `d = {value}`        | `bobbinOuterL` (mm)     | `"d = --"`    |
| `#svg_h`     | `h = {value}`        | `bobbinHeightPri` (mm)  | `"h = --"`    |

### Label Assignment Logic (from Step 13 in app.js)
```javascript
// Dimension a: inner width
document.getElementById("svg_a").textContent =
    bobbinInnerW !== null ? `a = ${bobbinInnerW}` : "a = --";

// Dimension b: outer width
document.getElementById("svg_b").textContent =
    bobbinOuterW !== null ? `b = ${bobbinOuterW}` : "b = --";

// Dimension c: inner length
document.getElementById("svg_c").textContent =
    bobbinInnerL !== null ? `c = ${bobbinInnerL}` : "c = --";

// Dimension d: outer length
document.getElementById("svg_d").textContent =
    bobbinOuterL !== null ? `d = ${bobbinOuterL}` : "d = --";

// Dimension h: height
document.getElementById("svg_h").textContent =
    bobbinHeightPri !== null ? `h = ${bobbinHeightPri}` : "h = --";
```

### Dimension Definitions

| Label | Engineering Meaning                   | Formula                                                      |
|-------|---------------------------------------|--------------------------------------------------------------|
| `a`   | Bobbin inner width (core slot width)  | `tongueWidth + coreGapBobbin`                                |
| `b`   | Bobbin outer width                    | `bobbinInnerW + (2 * bobbinOuterClearUsed)`                  |
| `c`   | Bobbin inner length (core slot length)| `stackHeight` (direct assignment)                            |
| `d`   | Bobbin outer length                   | `bobbinInnerL + (2 * bobbinOuterClearUsed)`                  |
| `h`   | Bobbin height                         | `bobbinHeightPri` (user input — no formula applied)          |

### Rounding Applied to SVG Labels
- NONE. The raw float values from the JS variables are used directly in the
  `textContent` strings. No formatting or rounding is applied before display.
- `bobbinInnerL` = `stackHeight` exactly (no rounding).
- `bobbinHeightPri` = user input value exactly (no rounding).
- `bobbinInnerW`, `bobbinOuterW`, `bobbinOuterL` = raw float results (no rounding).

### When Updated
- Updated during **every** invocation of `calculate()` in Phase 4 Step 13.
- Updated for BOTH inline and modal elements (see SVG Instance 2 below).

- Uses the same `bobbinInnerW`, `bobbinOuterW`, `bobbinInnerL`, `bobbinOuterL`,
  and `bobbinHeightPri` JS variables that were set during Step 13.
- Because both inline and modal updates occur within the same `calculate()` call,
  they always show identical values.

